# Исправление проблемы с загрузкой изображений на Render

Проблема заключалась в том, что Render использует **эфемерную файловую систему**. Все файлы, загруженные в папку `public/uploads`, удаляются при каждом перезапуске сервера или обновлении кода. Кроме того, без правильной настройки прав доступа (Service Account) Firebase Storage не мог сохранить файлы.

## Что было исправлено:
1.  **Логика загрузки**: Теперь сервер в первую очередь пытается загрузить файл в **Firebase Storage** (постоянное облачное хранилище).
2.  **Публичные ссылки**: Изменен формат ссылок на `https://storage.googleapis.com/BUCKET_NAME/FILE_NAME`, что более надежно для прямого отображения в браузере.
3.  **Поддержка Service Account**: Добавлена возможность авторизации через переменную окружения, чтобы у сервера были права на запись в Firebase.

## Инструкция по настройке на Render:

Для того чтобы изображения сохранялись навсегда, вам нужно добавить **переменные окружения (Environment Variables)** в панели управления Render:

1.  **FIREBASE_SERVICE_ACCOUNT**:
    *   Зайдите в Firebase Console -> Project Settings -> Service Accounts.
    *   Нажмите "Generate new private key". Скачается JSON-файл.
    *   Откройте этот файл, скопируйте всё содержимое и вставьте в значение переменной `FIREBASE_SERVICE_ACCOUNT` на Render.
    *   *Совет: Если Render ругается на формат, можно закодировать содержимое в Base64 и вставить строку.*

2.  **FIREBASE_PROJECT_ID**: ID вашего проекта (например, `gen-lang-client-0196243213`).
3.  **FIREBASE_STORAGE_BUCKET**: Название бакета (например, `gen-lang-client-0196243213.firebasestorage.app`).
4.  **GEMINI_API_KEY**: Ваш ключ для работы чат-бота.

## Если вы не хотите настраивать Firebase Storage:
Без этих переменных изображения будут сохраняться "локально", но они **пропадут** при следующем обновлении сайта на Render. Это особенность платформы Render. Для полноценной работы сайта с админ-панелью использование внешнего хранилища (как Firebase Storage) обязательно.
